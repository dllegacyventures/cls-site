AI Agents for Business

An AI agent isn't a chatbot with better manners. It's a piece of software that gets a task, uses tools to get it done and keeps working until there's a result. That difference decides whether the project pays off.

A guide by Mario De Luca · Updated Oct 14, 2026 · Figures from my own projects · Auf Deutsch

In short: An agent is worth it when a process is recurring, can be expressed in text or data, and is checkable. Building it is rarely the problem – the problem is the missing sign-off. An agent without a review step creates work instead of taking it off your plate.

Chatbot, assistant, agent: the difference in one sentence

These three words get sold interchangeably, even though they mean different prices, risks and results. The dividing line is always the same: how much is the system allowed to do on its own before a human looks at it?

LevelWhat it doesWhere it livesRisk
Chatbotanswers questions from a fixed body of knowledgewebsite, support widgetlow – a wrong answer
Assistantwrites, summarizes, drafts; a human takes it from therenext to the employeelow – lost time
Agentpulls data, decides intermediate steps, writes into systemsinside the process, with access rightshigh – it acts

The sentence I hear in almost every first call: “We want an agent.” Nine times out of ten, what they mean is an assistant – and that's the cheaper, faster, more honest solution. You only need a real agent when the process has to start and finish on its own.

When an agent pays off – and when it doesn't

I test every process against three questions. If it fails one, I don't build it as an agent.

  1. Does it recur? Below ten repetitions a month, doing it by hand is cheaper than any automation.
  2. Does it live in text or data? Anything that only exists in an employee's head has to be written down first. That step is the real work.
  3. Can the result be checked? If nobody can say “right” or “wrong” within five seconds, the review step is missing – and the agent becomes a problem.

Processes that hold up in practice

  • Researching and pre-qualifying contacts and companies
  • Drafting proposals and texts from the same building blocks every time
  • Call notes → summary → CRM entry
  • Scheduling and follow-up sequences, including reminders
  • Daily reports pulled from scattered sources (chat, spreadsheet, CRM)
  • Preparing images, videos and documents in a fixed format

Processes I deliberately don't automate

  • The sales conversation itself. People buy from people; a clone on the phone burns the trust that carries the deal.
  • Anything that legally needs a human – contracts, terminations, price commitments.
  • One-off special cases. Automating them costs more than they will ever save.

How an agent gets built: five steps

This is the order I work in – on client projects and in my own company.

1. Record the process, don't describe it

For one week, every single step gets logged: input, decision, output. Not how it's supposed to work, but how it actually runs. Most agent ideas die in this step, and that's a good thing – they would have died later at a higher price.

2. Draw the line

What is the agent allowed to do alone, and what does it hand to a human? I write that line down as one sentence before a single line of code exists. An example from my own company: the agent may build drafts and write data, but it may send nothing to the outside world.

3. Tools, not knowledge

An agent is only as good as its access: CRM, calendar, database, file storage, search. Every tool gets its own permissions – read and write kept separate. An agent with full access isn't an agent, it's an open gate.

4. A reviewer that isn't the agent

The most important building block, and the one that's almost always missing: a second, independent check of the result. In my setup, a separate pass checks against a fixed list – are the numbers, fields, format and recipient right? If you let the same agent review its own output, you get praise, not control.

5. Handover with an emergency brake

A place where you can see what the agent did, and a switch that turns it off. Without both, nobody on the team trusts it – and an agent nobody trusts gets worked around.

What I've built with it myself

I don't sell anything that isn't running in my own company. Three examples:

  • Sales groundwork: for my website campaign aimed at restaurants, the pipeline built 616 finished demo websites from address data and prepared 522 letters with a personal reference – before the first conversation took place. The human does the conversation, the machine does the groundwork.
  • Internal operations assistant: a system on a dedicated machine on my own network reads along, keeps track of open threads and writes a daily report every evening from chat, spreadsheet and CRM. It doesn't send anything by itself – it prepares. I've written about it in ESIS, my AI operating system.
  • Software assembly line: jobs are split into specification, build, test, review and release – each role is its own pass with an empty context. The reviewer only sees the code diff and the acceptance criteria, never the builder's reasoning. That's exactly why it finds things.

Two of these software jobs cost 52 and 114 US dollars in model costs – measured, not estimated. More on pricing: How much does an AI agent cost?

Frequently asked questions

What's the difference between a chatbot and an AI agent?

A chatbot answers. An agent acts: it gets a task, uses tools such as a CRM, calendar or database, and works through several steps on its own until there's a result. That's why an agent needs permissions, limits and a review step – and a chatbot doesn't.

Do I need to know how to code to use an AI agent?

For simple chains, no – no-code builders like n8n or the automation features of the big providers get you a long way. As soon as the agent writes into real systems, needs separate permissions and has to be checked, you need someone who can read code. Otherwise nobody notices when it quietly does the wrong thing.

How long does it take to build an AI agent?

Building a single, clearly scoped process takes days, not months. The time goes into recording the process and signing it off. If you show up with a finished process description, you can be live in a week; if you first have to find out how the process really runs, it takes three.

Which processes should I start with?

The one that happens most often and whose result can be checked in five seconds. Usually that's research, pre-qualification or moving call notes into the CRM – not the conversation itself.

Is an AI agent GDPR-compliant?

That isn't decided by the AI but by where the data is processed and under which contract. You need a data processing agreement with the model provider, an entry in your records of processing activities, and a decision about which personal data goes in at all. For a binding assessment of your specific case, bring in a data protection officer or a lawyer – I'm neither.

Will an AI agent replace employees?

In my company it replaces groundwork, not people: research, drafts, data transfers, reports. What remains is the conversation, the decision and the responsibility – and those need more time, not less.
